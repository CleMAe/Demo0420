# 智能办公智能体接口联动设计

## 背景

智能办公智能体负责多流程文档审查与办公协同，现有前端 Demo 只展示静态 tab 文案。此次改造聚焦当前模块，新增后端结构化审查接口，并让前端 Demo 调用接口展示审查结果。

## 目标

- 为智能办公智能体新增 `POST /api/smart-office/review` 接口。
- 支持四类办公场景：报销单据、简历筛选、招标文件、合同审核。
- 返回风险等级、评分、风险点、建议和下一步动作。
- 前端 Demo 能选择场景、输入文本、调用接口并渲染结果。
- 保持现有 RBAC、产品可见性和产品名称不变。

## 非目标

- 不接入真实大模型或 DeepSeek。
- 不新增数据库表或审查历史持久化。
- 不调整其他产品模块的名称、权限、行业或技术栈。

## 后端设计

新增 Pydantic 模型：

- `SmartOfficeReviewRequest`
- `SmartOfficeFinding`
- `SmartOfficeReviewResult`
- `SmartOfficeReviewResponse`

新增接口 `POST /api/smart-office/review`：

- 要求登录用户访问。
- 校验 `product_id` 必须属于 `智能办公智能体`。
- 使用现有 `product_visible_for_user` 检查权限。
- 根据 `scenario` 和 `content` 执行本地规则审查。

规则引擎按场景返回稳定模拟结果：

- `expense`：关注金额超标、发票、招待对象、出差说明。
- `resume`：关注岗位匹配、经验年限、技能关键词和风险提示。
- `tender`：关注相似描述、资质条件、评分项和围标风险。
- `contract`：关注责任上限、付款周期、违约条款和法务复核。

## 前端设计

改造 `portal-demos.js` 中的 `demoSmartOffice`：

- 保留四个场景 tab。
- 增加文本输入区域和默认样例文本。
- 增加“开始审查”按钮。
- 调用 `/api/smart-office/review`。
- 展示风险等级、评分、结论、风险点、处理建议和下一步动作。
- 接口失败时在 Demo 内显示错误提示，不影响页面其他模块。

## 测试设计

后端新增 pytest：

- 已登录普通用户可对智能办公智能体发起审查并拿到结构化结果。
- 使用其他产品 `product_id` 会返回 404。
- 不同场景能返回对应场景名称和风险点。

前端新增 Node 测试：

- `PortalDemos.mount` 挂载智能办公智能体后包含“开始审查”等交互入口。

## 风险与约束

- 规则引擎是演示逻辑，不代表真实法律、人事、采购或财务结论。
- 所有改动应限制在智能办公模块相关代码和测试文件。
- 不修改依赖文件，不引入前端框架。
